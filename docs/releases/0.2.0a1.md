# Streamcase 0.2.0a1 release notes

**Status: candidate, not yet tagged or published.** Issue
[#156](https://github.com/SEPURI-SAI-KRISHNA/streamcase/issues/156) prepares
the reviewed source. Issue
[#157](https://github.com/SEPURI-SAI-KRISHNA/streamcase/issues/157) controls
tagging, protected PyPI publication, and published-artifact verification.
Check [PyPI](https://pypi.org/project/streamcase/) before attempting the
version-pinned installs below.

## What's new since 0.1.0a2

- Immutable progress and state-operator snapshots in `ScenarioResult.progress`.
  The Spark runner captures progress associated with callback-backed triggers,
  including across checkpoint-preserving restarts.
- `assert_input_row_count`, `assert_watermark`, and `assert_state_metric` for
  explicit action/trigger selections. Missing reports or metrics produce
  contextual failures rather than invented values.
- A separate `spark35` extra for PySpark 3.5.9 and later 3.5 patches, tested
  alongside the existing Spark 4.2 `spark` extra.
- A separately installable `pytest` extra and explicitly loaded
  `streamcase.pytest_plugin`. Its function-scoped `streamcase_runner` fixture
  keeps generated files under each test's temporary directory and leaves
  ownership of the Spark session with the caller.

The existing scenario, batch, restart, result, assertion, and public Spark
runner APIs remain available. Core installation still requires neither
PySpark nor pytest.

## Tested compatibility

| Component | Tested combination |
| --- | --- |
| Backend-independent package | Python 3.10, 3.11, 3.12, and 3.13; no Java or PySpark required |
| Spark 4.2 runner and pytest fixture | Python 3.11, Java 17, and PySpark 4.2.x in local mode |
| Spark 3.5 runner and pytest fixture | Python 3.11, Java 17, and PySpark 3.5.9 or later 3.5 patches in local mode |

Both Spark lines run integration tests and clean wheel/sdist smoke checks with
the `pytest` extra in CI. The [compatibility policy](../spark-compatibility.md)
defines the narrower Streamcase support claim; passing core tests on another
Python version does not establish Spark runner compatibility there. The
candidate PR and merged `main` must pass their own gates before tagging.

## Installation after publication

Choose **one** Spark extra. The commands below only work after `0.2.0a1`
appears on PyPI:

```shell
python -m pip install "streamcase==0.2.0a1"
python -m pip install "streamcase[spark]==0.2.0a1"
python -m pip install "streamcase[spark35]==0.2.0a1"
python -m pip install "streamcase[pytest,spark]==0.2.0a1"
```

For the pytest fixture with Spark 3.5, use
`"streamcase[pytest,spark35]==0.2.0a1"` instead. Install a Java 17 JDK
separately for either Spark line. Before publication, use an editable source
checkout as described in the [pytest guide](../pytest-integration.md).

## Alpha limits and change expectations

- This is an **experimental alpha**, not a stable API or production-support
  commitment. Later alphas may make breaking changes.
- The runner uses a JSON file stream, explicit input schema, and local Spark
  execution. Remote clusters, other Python/Java/Spark combinations, Kafka,
  Delta Lake, PyFlink, production monitoring, and checkpoint mutation are not
  part of this release.
- Spark controls event-time and state-store progress. A watermark need not
  advance for every logical `Batch`, and optional state metrics may be absent;
  assertions distinguish absence from a reported zero.
- The pytest plugin is opt-in. It does not create or stop a Spark session;
  tests must provide a caller-owned session fixture.

The [release checklist](../releasing.md) and #157 govern the final tag,
protected Trusted Publishing job, distribution hashes, and clean-install
verification. GitHub release notes do not carry wheel or source-distribution
assets; those files are published on PyPI.
